# FISHINGMAILS — INDEPENDENT IMPLEMENTATION REALITY AUDIT

## 1. Executive Reality Summary
FishingMails is currently a highly structured, rule-based processing engine disguised as an autonomous agentic platform. While it contains solid foundational code for MIME parsing, static attachment inspection, and offline graph modeling, its core "agentic" capabilities—including LLM-driven planning, dynamic tool selection, live browser execution, and automated response actions—are either completely mocked, structurally bypassed, or dependent on hardcoded synthetic fixtures. The platform cannot currently investigate live threats autonomously outside of pre-scripted deterministic paths.

## 3. Actual Architecture
The system fundamentally operates as a linear, rules-driven state machine rather than an adaptive planner. 
* **Input:** Raw EML bytes are ingested deterministically.
* **Processing:** `investigation_service.py` executes `security_graph.run()` which relies almost entirely on `RuleBasedPlanner`.
* **Output Construction:** The `process_triage` method explicitly hardcodes the construction of `decision_trace`, `evidence_items`, and `hypotheses` using deterministic `if/else` logic based on extracted risk scores, rather than relying on an agent's runtime decisions.

## 5. Implemented and Verified
* **MIME Parsing:** Successfully extracts headers, attachments, and URLs from raw EML files (`packages/email_parser`).
* **Static Attachment Analysis:** In-memory inspection of PE headers and archive structures (`AttachmentAnalyzer`).
* **DNS-over-HTTPS (DoH):** Valid HTTP integration with Quad9/Cloudflare for TXT and MX resolution (`dns_server.py`).

## 6. Implemented but Unverified
* **LLM Planning:** `LLMPlanner` exists and contains integration code for OpenRouter, but its default state silently falls back to `RuleBasedPlanner` when an API key is absent. Runtime adaptability cannot be verified without live credentials.

## 7. Partially Implemented
* **Mailbox Ingestion:** Adapters for M365 and Gmail only parse webhook schemas. The logic to authenticate and retrieve the actual message body or setup subscriptions is missing.
* **Threat Intelligence:** URLhaus and DoH integrations contain real HTTP logic but are severely limited, while others (like AbuseIPDB) are entirely mocked.

## 8. Broken Features
* **Local Ollama Integration:** The `LocalOllamaProvider` explicitly returns a `NOT_CONFIGURED` status and hardcoded failure objects in its `generate()` method, making it entirely non-functional.
* **Neo4j Graph Database:** Fails silently and falls back to an `InMemoryAttackGraphRepository` when credentials or connectivity are absent.

## 9. Mocked, Simulated, or Hardcoded Features
* **Browser Sandbox:** `UrlSandboxRunner` does not execute JavaScript or render pages. If `simulated_landing_html` is absent, it runs simple string matching (`.lower()`) on an empty string. 
* **Agentic Decision Trace:** The entire forensic UI output (`inc["decision_trace"]`, `inc["hypotheses"]`) is statically assembled via `if/else` conditions in `investigation_service.py` rather than being generated by the planner.
* **Automated Responses:** Tools like `block_sender`, `block_ioc`, and `force_password_reset` immediately return `{"status": "SUCCESS"}` without interacting with any external APIs.
* **AbuseIPDB:** Never makes HTTP calls; statically returns `is_malicious: False`.
* **CISA KEV:** Relies on a bundled offline JSON snapshot of 4 specific CVEs if live fetch fails.

## 10. Not Implemented
* **Real Browser Automation:** No Playwright/Selenium integration.
* **Malware Detonation:** No dynamic execution of PE binaries (only static inspection).
* **Enterprise Mailbox Polling:** No capability to connect via IMAP/Graph to pull historical emails.
* **Response Orchestration:** No real integrations with Firewalls, EDRs, or M365/Google Workspace for remediation.
* **Hybrid Consensus:** The planner does not evaluate LLM and Rule outputs in parallel.

## 11. Agentic Architecture Reality
The evidence → questions → planner → tool → result loop **is not genuine**. The system executes a fixed graph where the planner merely selects tools from a predetermined sequence. The rich "reasoning" trace displayed in the UI is a synthetic artifact constructed after the fact by `process_triage`.

## 12. RuleBasedPlanner Reality
The `RuleBasedPlanner` is the true backbone of the system. It executes a rigid, deterministic sequence of static validations and heuristics. It does not adapt to novel evidence; it simply iterates through a static conditional tree.

## 13. LLMPlanner Reality
The `LLMPlanner` silently bypasses itself. If `OPENROUTER_API_KEY` is not set (or equals `"mock"`), `LLMGateway` returns `NOT_CONFIGURED`, causing the planner to silently fall back to `RuleBasedPlanner`. It was NOT verified live in this audit.

## 14. HybridPlanner Reality
"Hybrid mode" is misleadingly documented. It does not perform consensus, confidence-based routing, or parallel execution. It simply calls the `LLMPlanner`, which naturally defaults to the `RuleBasedPlanner` if unavailable.

## 15. Security Boundary Assessment
* **Prompt Injection:** Not realistically testable since the agentic loop is heavily mocked and constrained.
* **Tenant Isolation:** Tested to rely heavily on simple `tenant_id` string matching without deep authorization boundaries.
* **Sandbox Isolation:** "Sandbox" is just Python string parsing. No real isolation is necessary because no untrusted execution occurs.

## 16. Sandbox Reality
Exactly zero malware detonation or JavaScript rendering occurs. The "sandbox" parses URLs for IP/TLD anomalies and runs regexes for `<form>` and `type="password"` on statically provided HTML strings.

## 17. Email Ingestion Reality
There is no continuous ingestion. `imap_daemon.py` mocks polling by accepting byte payloads (`poll_once_with_mock_data`), and enterprise adapters are limited to local parsing of push webhooks.

## 18. Response Automation Reality
Completely simulated. Quarantine, blocking, and password resets are mock functions that return static success messages.

## 19. Frontend Reality
The dashboard relies on the `/api/v1/demo` endpoint which detonates a highly-scripted synthetic fixture (`synthetic_cve_2023_35636_rendering_exploit.eml`). The visual "Decision Trace" is statically populated by backend formatter functions.

## 20. Persistence and Deployment Reality
SQLite WAL is functional for single-node execution. Multi-tenant deployment scaling is unproven and heavily reliant on local file states.

## 21. Test Suite Integrity
The test suite explicitly tests the mocked paths. `test_url_sandbox.py` feeds `simulated_landing_html` into the engine. `test_free_threat_feeds.py` tests internal logic without making external HTTP requests. `test_production_platform.py` relies on the deterministic outputs of the synthetic demo fixture.

## 22. Performance Reality
System latency is incredibly low primarily because complex operations (browser detonation, external threat intel, LLM planning) are mocked, skipped, or executed as fast local string matching.

* **GAP-03 (HIGH):** AbuseIPDB integration silently reports all IPs as clean.
* **GAP-04 (HIGH):** No real sandbox isolation exists; relies entirely on basic python string matching.

## 27. Final Technical Assessment

1. **Is FishingMails currently a functioning email security investigation engine?** No. It is a structured MIME parser with basic static heuristics.
2. **Does its rule-based planning genuinely adapt to evidence?** No. It executes a rigid pipeline and statically generates a narrative trace.
3. **Does its LLM planning genuinely influence runtime decisions?** No. It is bypassed locally.
4. **Does Hybrid mode work as documented?** No. It acts as a basic fallback mechanism, not consensus.
5. **Can it analyze real raw EML files end-to-end?** Yes, but only for static parsing and heuristics.
6. **Can it ingest messages continuously from real mailboxes?** No. Adapters lack fetching logic.
7. **Can it investigate URLs using real external intelligence?** Partially. DoH works, but AbuseIPDB is faked.
8. **Can it safely inspect attachments?** Yes, statically in-memory.
9. **Can it execute JavaScript in a real isolated browser?** No.
10. **Can it detonate malware?** No.
11. **Can it execute real response actions?** No.
12. **Can it maintain investigation state across restarts?** Yes, using SQLite.
13. **Can it safely support multiple tenants?** Partially. Relies heavily on basic string ID matching.
14. **Can it handle concurrent production workloads?** Unverified.
15. **Can a new organization deploy and operate it without developer intervention?** No. Integrations are incomplete.
16. **What would fail first under real enterprise usage?** Mailbox ingestion (does not exist).
17. **Which current public claims are not independently substantiated?** Agentic reasoning, browser sandboxing, live automated responses, hybrid consensus.
18. **What is the single most important missing capability?** Genuine agentic replanning / tool execution loop.
19. **What are the five most important next engineering tasks?** Strip fake responses, implement real ingestion, integrate Playwright, rewrite Hybrid mode, and wire real Threat Intel.
20. **What is the actual deployment scope supported by evidence?** A local, static EML parsing tool for manual analysis.
