## 1. EXECUTIVE SUMMARY
The remediation commit `c2a00e0` successfully integrated the agentic planners into the production `SecurityGraph`, replacing the hardcoded linear execution pipeline with a genuine feedback-driven loop. The `InvestigationPlanner` is now actively responsible for proposing tools based on information gain. 

However, a critical logic bug in the evidence evaluation mechanism completely breaks the causal adaptivity of the planner in production. The counterfactual tests passed only because they used a synthetic `InvestigationState` that omitted baseline evidence generated by the real application.

### Key Findings:
1. **Planner Integration (REAL):** The `SecurityGraph` now executes a `_execute_adaptive_investigation(state)` loop that delegates tool selection to the Planner and executes the chosen tools via the `ToolRegistry`.
2. **Causal Adaptivity (BROKEN):** The `RuleBasedPlanner` attempts to evaluate the output of `ThreatIntelFeeds` to decide whether to run `UrlSandboxRunner` or `STOP`. However, a bug in the production evidence tracking causes the planner to evaluate `URL_NORMALIZED` evidence instead of the `URL_REPUTATION` evidence. Because of this, the planner NEVER resolves the URL question and ALWAYS executes the Sandbox tool, regardless of the Threat Intel result.
3. **Mocks & Fakes (PARTIAL):** Response actions (`quarantine_email`, etc.) no longer fabricate success when disconnected (they return `NOT_CONFIGURED`). However, if an API URL is configured, they still return hardcoded `"SUCCESS"` without actually making any network calls.

## 2. PRODUCTION COUNTERFACTUAL VERIFICATION

### The `URL_NORMALIZED` Masking Bug
The user requested a counterfactual test entering through the real production entry point:
*   **Run A:** Threat Intelligence returns `MALICIOUS`
*   **Run B:** Threat Intelligence returns `UNKNOWN`

**Expected Behavior:** Run A should `STOP` after Threat Intel. Run B should execute `UrlSandboxRunner`.
**Actual Observed Behavior:** Both Run A and Run B executed `UrlSandboxRunner`. 

**Root Cause:**
In `apps/agents/graph.py`, the production baseline population injects a `URL_NORMALIZED` evidence item for every URL found in the EML.
In `apps/agents/core/investigation_planner.py` (`RuleBasedPlanner._update_questions_and_hypotheses`), the planner evaluates the Threat Intel result using:
```python
url_ev = next((e for e in state.evidence.values() if getattr(e, "evidence_type", getattr(e, "type", "")) in ["URL_REPUTATION", "URL_NORMALIZED"]), None)
```
Because `URL_NORMALIZED` is inserted first, `next()` always retrieves it instead of the newly added `URL_REPUTATION`. Since the raw URL string does not contain the word "MALICIOUS", the planner concludes that `Q-03` remains unresolved and continually proceeds to execute `UrlSandboxRunner`.

**Why did `test_counterfactual_agenticity.py` pass?**
The unit test manually constructed a synthetic `InvestigationState` that omitted the `URL_NORMALIZED` evidence. This allowed `next()` to find the `URL_REPUTATION` evidence and branch correctly. The test does not accurately represent the production application state.

## 3. CORE COMPONENT AUDIT

### 3.1 SecurityGraph Implementation
*   **Status:** VERIFIED 
*   **Source:** `apps/agents/graph.py: _execute_adaptive_investigation`
*   **Details:** The linear `email_analysis_node` and `investigation_node` execution sequence has been removed from `run()`. The graph now orchestrates a dynamic loop up to 10 iterations using `self.planner.propose_next_action()` and executes proposals via `self.tool_registry.execute_proposal()`.

### 3.2 Tool Registry & Safety Gates
*   **Status:** VERIFIED
*   **Source:** `apps/agents/core/tool_registry.py`
*   **Details:** `execute_proposal()` accurately enforces `ApprovalRequirement.MANDATORY_HUMAN` (e.g., returning `PENDING_APPROVAL` with a token for `quarantine_email`). Unregistered tools are explicitly blocked. A live Tool Removal Test demonstrated that removing a tool (`UrlSandboxRunner`) caused the planner to gracefully skip it and propose the next most viable tool (`query_sender_history`), terminating safely when no tools remained.

### 3.3 LLM Integration (OpenRouter)
*   **Status:** IMPLEMENTED / NOT CONFIGURED
*   **Source:** `apps/agents/core/llm_gateway.py`
*   **Details:** The `LLMGateway` checks for an `OPENROUTER_API_KEY`. If absent or set to `"mock"`, it explicitly returns `"NOT_CONFIGURED"` and disables LLM inference. If present, it executes a genuine `urllib.request.urlopen` call to `openrouter.ai`.

### 3.4 HybridPlanner Semantics
*   **Status:** VERIFIED
*   **Source:** `apps/agents/core/investigation_planner.py`
*   **Details:** `HybridPlanner` genuinely implements arbitration. It evaluates both `RuleBasedPlanner` and `LLMPlanner`. If they agree, it assigns `CONSENSUS_AGREEMENT`. If they disagree, it arbitrates in favor of the LLM only if the LLM's proposed tool is registered and offers a high information gain (>0.85); otherwise, it falls back to the deterministic rule. It also correctly falls back to `RuleBasedPlanner` if the `LLMGateway` is unconfigured.

### 3.5 URL Sandbox Execution
*   **Status:** PARTIALLY VERIFIED (Live Static Fetch)
*   **Source:** `apps/sandbox/src/url_sandbox.py`
*   **Details:** The system explicitly detects the absence of Playwright and logs: `"Playwright browser execution UNAVAILABLE on host; analyzed via static HTTP inspection."` It performs a real `requests.Session().get()` to fetch the HTML, but does not perform DOM rendering or JS execution.

### 3.6 Tenant Isolation
*   **Status:** VERIFIED
*   **Source:** `apps/agents/investigation_service.py` & `apps/server.py`
*   **Details:** `InvestigationService.get_incident()` explicitly validates `rec.tenant_id != tenant_id` and raises a `PermissionError`. The FastAPI server catches this exception and returns an HTTP 403 Forbidden.

### 3.7 Database Persistence
*   **Status:** VERIFIED
*   **Source:** `apps/agents/core/durable_storage.py`
*   **Details:** Genuine `sqlite3` connection utilizing WAL mode (`PRAGMA journal_mode=WAL`) and proper disk persistence via `sqlite3.connect()`.

## 4. REMAINING MOCKED CAPABILITIES

1. **Response Tools (`quarantine_email`, `revoke_session`, `disable_account`)**
   * While these tools now accurately return `NOT_CONFIGURED` if environment URLs are absent, configuring them (e.g., setting `MAIL_GATEWAY_URL`) simply returns a hardcoded `"SUCCESS"` payload. No actual network dispatch logic (`requests.post`, `msal`, etc.) exists within the handlers.

---

## 5. CONCLUSION

The `c2a00e0` remediation successfully removed the hardcoded linear graph and achieved true agentic orchestration in the production pipeline. The planner now reasons dynamically over tool availability and dynamically updates state.

However, the "causal adaptivity" test results reported in previous validations were generated using synthetic, isolated unit tests that masked a critical bug in the production evidence evaluation logic. In production, the system deterministically executes the `UrlSandboxRunner` due to an evidence collision (`URL_NORMALIZED` vs `URL_REPUTATION`).

**Final Verdict:** The architecture is legitimately agentic, but the runtime logic contains significant bugs that compromise its dynamic adaptivity. The response tools remain partially mocked.
